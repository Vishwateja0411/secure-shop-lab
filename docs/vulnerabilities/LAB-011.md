# LAB-011: Business Logic Flaws (Price & Quantity Manipulation)

## Overview
* **Vulnerability Name**: Business Logic Flaw in Checkout Calculation
* **Vulnerability ID**: LAB-011
* **OWASP Category**: A04:2021 — Insecure Design
* **Location in Source Code**: `backend/app/api/cart.py` (`POST /api/cart/checkout`) & `frontend/js/app.js`

---

## Why It Is Vulnerable (Root Cause)
The checkout calculation makes several flawed business logic assumptions:
1. **Client Price Trust**: The backend accepts a client-provided `client_price` field in the checkout payload and calculates order totals using the client's price rather than the authoritative database price.
2. **Missing Quantity Validation**: The endpoint does not assert `quantity > 0`. A client can submit negative quantities (e.g. `quantity = -5`), offsetting the cost of legitimate items.
3. **Uncapped Coupon Usage**: Discount coupons can be reused repeatedly across multiple orders because coupon usage counts are not enforced.

---

## Security Impact
- **Financial Fraud**: Attackers can purchase merchandise for $0.00 or negative amounts.
- **Inventory Disruption**: Submitting negative order quantities can corrupt inventory calculations.

---

## How to Reproduce Locally
1. Start the lab in vulnerable mode (`SECURE_MODE=false`).
2. Log in as user `alice`.
3. Add a product (e.g. "Hardware Security Key", $49.99) to your shopping cart.
4. In the cart modal, edit the quantity to `-2` or enter an overridden price of `0.01` in the client price box.
5. Alternatively, submit the following payload via curl:
   ```bash
   curl -X POST -H "Authorization: Bearer <alice_token>" -H "Content-Type: application/json" \
        -d '{"items": [{"product_id": 1, "quantity": -1, "client_price": null}], "shipping_address": "Test Street"}' \
        http://localhost:8000/api/cart/checkout
   ```

---

## Expected Insecure Behavior
The checkout completes with status `200 OK`, creating an order with a total amount of `$0.00` or negative balance.

---

## Secure Remediation
1. **Authoritative Server Pricing**: Calculate all item prices strictly using records fetched directly from the database `products` table. Never allow client payloads to specify pricing.
2. **Strict Quantity Bounds**: Validate that `quantity` is an integer strictly greater than zero (`quantity > 0`).
3. **Atomic Coupon Enforcement**: Verify coupon validity and increment usage counts within the checkout transaction.

---

## Secure Code Example
```python
# Secure checkout implementation in backend/app/api/cart.py
for item in req.items:
    if item.quantity <= 0:
        raise HTTPException(status_code=400, detail="Item quantity must be greater than zero.")
    
    product = db.query(Product).filter(Product.id == item.product_id).first()
    if not product:
        raise HTTPException(status_code=404, detail=f"Product {item.product_id} not found.")
    
    if product.stock < item.quantity:
        raise HTTPException(status_code=400, detail=f"Insufficient stock for {product.name}.")

    # Price calculated exclusively from authoritative server database record
    unit_price = product.price
    total_amount += unit_price * item.quantity
```
