# LAB-005: Cross-Site Request Forgery (CSRF)

## Overview
* **Vulnerability Name**: Cross-Site Request Forgery on Email Modification
* **Vulnerability ID**: LAB-005
* **OWASP Category**: A01:2021 — Broken Access Control
* **Location in Source Code**: `backend/app/api/users.py` (`POST /api/users/csrf-change-email`)

---

## Why It Is Vulnerable (Root Cause)
The state-changing endpoint `/api/users/csrf-change-email` accepts sensitive account changes authenticated via ambient browser cookies (`Cookie: session_token=...`) without verifying:
1. An anti-CSRF synchronizer token header (`X-CSRF-Token`).
2. The `Origin` or `Referer` headers.
3. Strict `SameSite` cookie flags (`SameSite=Lax` or `SameSite=Strict`).

Consequently, an external malicious website can host a hidden form that submits a POST request to this endpoint; the victim's browser will automatically attach their session cookie.

---

## Security Impact
- **Account Takeover**: An attacker can change the victim's registered email address to an attacker-controlled inbox, subsequently triggering a password reset flow to take over the account.

---

## How to Reproduce Locally
1. Start the lab in vulnerable mode (`SECURE_MODE=false`).
2. Log in as user `alice`.
3. In a separate browser tab or local test page, create an HTML file with an auto-submitting form:
   ```html
   <form action="http://localhost:8000/api/users/csrf-change-email" method="POST">
       <input type="hidden" name="email" value="attacker@evil.lab" />
       <input type="submit" value="Click for free prizes" />
   </form>
   <script>document.forms[0].submit();</script>
   ```
4. Open the test page while authenticated.

---

## Expected Insecure Behavior
The request succeeds with status `200 OK`, updating Alice's account email without her consent or knowledge.

---

## Secure Remediation
1. **Anti-CSRF Tokens**: Require a custom header (`X-CSRF-Token`) containing a cryptographically secure token that cross-origin HTML forms cannot forge due to browser SOP.
2. **SameSite Cookies**: Configure `SameSite=Lax` or `SameSite=Strict` on session cookies so browsers do not send them in cross-site subrequests.

---

## Secure Code Example
```python
@router.post("/csrf-change-email")
def change_email_csrf_demo(
    email: EmailStr = Form(...),
    x_csrf_token: Optional[str] = Header(None),
    current_user: User = Depends(get_current_user),
    db: Session = Depends(get_db)
):
    if settings.SECURE_MODE:
        # Verify custom header presence and token length
        if not x_csrf_token or len(x_csrf_token) < 16:
            raise HTTPException(
                status_code=status.HTTP_403_FORBIDDEN,
                detail="CSRF verification failed: Missing or invalid X-CSRF-Token header."
            )

    current_user.email = email
    db.commit()
    return {"status": "success", "message": f"Email updated to {email}"}
```
