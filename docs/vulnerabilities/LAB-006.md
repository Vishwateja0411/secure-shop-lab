# LAB-006: Insecure File Upload

## Overview
* **Vulnerability Name**: Unrestricted File Upload in Profile Avatar
* **Vulnerability ID**: LAB-006
* **OWASP Category**: A04:2021 — Insecure Design / File Inclusion
* **Location in Source Code**: `backend/app/api/users.py` (`POST /api/users/upload-avatar`)

---

## Why It Is Vulnerable (Root Cause)
The file upload endpoint has multiple architectural security flaws:
1. **Raw Client Filename Used**: It directly saves files using `file.filename` supplied by the client without sanitization or randomization.
2. **Missing Extension Whitelist**: Files with extensions like `.html`, `.svg`, `.py`, or `.sh` are accepted.
3. **Missing MIME Validation**: The backend does not inspect magic bytes or content headers.
4. **No Size Limit**: Arbitrarily large files can be uploaded, consuming server storage.
5. **Accessible Web Directory**: Uploaded files are served directly from the `/uploads/` route.

---

## Security Impact
- **Stored XSS via HTML/SVG Upload**: Uploading an `.html` file or `.svg` with `<script>` tags creates a stored XSS payload served from the application's domain.
- **Remote Code Execution (RCE)**: In PHP/CGI environments, uploading executable scripts leads to complete server compromise.
- **Denial of Service**: Uploading gigantic files exhausts disk space.

---

## How to Reproduce Locally
1. Start the lab in vulnerable mode (`SECURE_MODE=false`).
2. Log in as user `alice`.
3. Create a test file named `test_avatar.html`:
   ```html
   <html><body><h1>Defaced via File Upload</h1><script>alert(document.domain)</script></body></html>
   ```
4. Navigate to the **Profile** view, click **Upload Avatar**, and select `test_avatar.html`.
5. Observe the response containing the URL: `/uploads/test_avatar.html`.
6. Open `http://localhost:8000/uploads/test_avatar.html` in the browser.

---

## Expected Insecure Behavior
The HTML file is accepted, written to disk with its original name, and executed in the browser when accessed.

---

## Secure Remediation
1. **Extension Whitelist**: Allow only safe image extensions (`.png`, `.jpg`, `.jpeg`, `.webp`).
2. **MIME Validation**: Validate `Content-Type` against permitted image types.
3. **Randomized Filename**: Generate a random UUID filename (e.g. `uuid.uuid4().hex + ext`) to prevent directory traversal and file overwrites.
4. **Size Enforcement**: Restrict uploads to a strict maximum limit (e.g. 2MB).

---

## Secure Code Example
```python
# Secure upload implementation in backend/app/api/users.py
ALLOWED_IMAGE_EXTENSIONS = {".png", ".jpg", ".jpeg", ".webp"}
ALLOWED_MIME_TYPES = {"image/png", "image/jpeg", "image/webp"}
MAX_FILE_SIZE = 2 * 1024 * 1024  # 2MB

content = await file.read()
if len(content) > MAX_FILE_SIZE:
    raise HTTPException(status_code=400, detail="File size exceeds 2MB limit.")

_, ext = os.path.splitext(file.filename.lower())
if ext not in ALLOWED_IMAGE_EXTENSIONS:
    raise HTTPException(status_code=400, detail="Invalid file extension.")

if file.content_type not in ALLOWED_MIME_TYPES:
    raise HTTPException(status_code=400, detail="Invalid MIME type.")

# Generate random unique filename
safe_filename = f"avatar_{uuid.uuid4().hex}{ext}"
file_path = os.path.join(settings.UPLOAD_DIR, safe_filename)

with open(file_path, "wb") as f:
    f.write(content)
```
