# LAB-009: Weak Authentication, Password Storage & Missing Rate Limiting

## Overview
* **Vulnerability Name**: Weak Password Policy, MD5 Storage & Missing Rate Limiting
* **Vulnerability ID**: LAB-009
* **OWASP Category**: A07:2021 — Identification and Authentication Failures
* **Location in Source Code**: `backend/app/auth/hashing.py`, `backend/app/security/rate_limiter.py`, & `backend/app/api/auth.py`

---

## Why It Is Vulnerable (Root Cause)
1. **Weak Password Policy**: In vulnerable mode, passwords of length 1 (e.g. `'1'` or `'a'`) are accepted during registration.
2. **Obsolete Hashing**: In vulnerable mode, passwords are saved using unsalted MD5 (`hashlib.md5(p.encode()).hexdigest()`), which is trivially cracked via precomputed rainbow tables.
3. **Missing Rate Limiting**: The `/api/auth/login` endpoint allows unlimited rapid authentication attempts without delay or lockout, enabling brute-force and credential stuffing attacks.
4. **Predictable Password Reset**: The password reset token is constructed from static strings and user IDs (`reset_{id}_static_12345`), allowing attackers to forge reset links.

---

## Security Impact
- **Account Takeover**: Brute-force attacks succeed rapidly on accounts with simple passwords.
- **Credential Cracking**: If the database is compromised, unsalted MD5 hashes can be cracked in seconds.
- **Unauthorized Password Reset**: Attackers can reset victim passwords by calculating predictable reset tokens.

---

## How to Reproduce Locally
1. Start the lab in vulnerable mode (`SECURE_MODE=false`).
2. Register a user with a single-character password (`password="1"`). The server accepts it with status `200 OK`.
3. Submit 20 rapid failed login attempts against `http://localhost:8000/api/auth/login`. In vulnerable mode, no 429 Too Many Requests response is ever issued.
4. Request a password reset for Alice (`alice@secureshop.lab`). Observe the generated predictable token:
   ```text
   reset_2_static_12345
   ```

---

## Expected Insecure Behavior
Weak passwords are accepted, unlimited brute-force attempts are permitted without throttling, and reset tokens follow easily guessable deterministic patterns.

---

## Secure Remediation
1. **Password Policy**: Require at least 8 characters with uppercase, lowercase, numbers, and symbols.
2. **Salted Adaptive Hashing**: Hash passwords using Bcrypt with cost factor >= 12 or Argon2id.
3. **Rate Limiting**: Limit failed logins to 5 attempts per minute per IP.
4. **Cryptographic Tokens**: Generate 256-bit secure random tokens (`secrets.token_hex(32)`) with a 15-minute expiration time.

---

## Secure Code Example
```python
# Secure password validation:
def validate_password_strength(password: str) -> tuple[bool, str]:
    if len(password) < 8:
        return False, "Password must be at least 8 characters long."
    if not any(c.isupper() for c in password):
        return False, "Password must contain an uppercase letter."
    if not any(c.isdigit() for c in password):
        return False, "Password must contain a number."
    if not any(c in "!@#$%^&*()-_=+[]{}|;:,.<>?" for c in password):
        return False, "Password must contain a special character."
    return True, ""

# Secure token generation:
token_str = secrets.token_hex(32)
```
