# LAB-003: Stored Cross-Site Scripting (Stored XSS)

## Overview
* **Vulnerability Name**: Stored Cross-Site Scripting in Product Reviews
* **Vulnerability ID**: LAB-003
* **OWASP Category**: A03:2021 — Injection (XSS)
* **Location in Source Code**: `backend/app/api/products.py` (`POST /api/products/{id}/reviews`) & `frontend/js/app.js` (`renderReviews`)

---

## Why It Is Vulnerable (Root Cause)
1. **Server-side**: The backend accepts arbitrary HTML and JavaScript tags in the `comment` field without sanitization or HTML entity encoding.
2. **Client-side**: The frontend application renders persisted reviews by assigning the comment directly to `innerHTML`:
   ```javascript
   // Unsafe DOM sink
   element.innerHTML = review.comment;
   ```
This combination allows HTML markup and inline scripts stored in the database to execute inside the browser of every subsequent user who visits that product's page.

---

## Security Impact
- **Session Hijacking**: In environments without `HttpOnly` cookie flags (`LAB-010`), injected scripts can read `document.cookie` and steal active user sessions.
- **Defacement & Phishing**: Injected scripts can render fake modal dialogues to capture victim credentials.

---

## How to Reproduce Locally
1. Start the lab in vulnerable mode (`SECURE_MODE=false`).
2. Log in as user `alice` or `bob`.
3. Open any product (e.g. "Hardware Security Key").
4. In the "Customer Reviews" form, enter a test HTML payload:
   ```html
   <img src=x onerror="alert('Stored XSS Lab Triggered!')">
   ```
5. Click **Submit Review**.

---

## Expected Insecure Behavior
The payload is saved into the database and immediately executed in the browser DOM upon rendering, triggering an alert box or image error handler.

---

## Secure Remediation
1. **Input Sanitization / Entity Encoding**: Entity-encode characters (`<`, `>`, `&`, `"`, `'`) using `html.escape()` before persisting or serving data.
2. **Safe Client DOM Binding**: Bind text via `element.textContent` rather than `innerHTML`.
3. **Content-Security-Policy**: Enforce strict CSP to restrict unauthorized inline script execution.

---

## Secure Code Example
```python
# Server-side remediation in backend/app/security/sanitizer.py
import html

def sanitize_comment(raw_text: str, secure_mode: bool = False) -> str:
    if not secure_mode:
        return raw_text
    return html.escape(raw_text, quote=True)
```

```javascript
// Client-side remediation in frontend/js/app.js
const commentHtml = isSecureMode ? escapeHtml(r.comment) : r.comment;
```
