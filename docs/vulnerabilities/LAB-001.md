# LAB-001: Broken Access Control (Insecure Direct Object Reference - IDOR)

## Overview
* **Vulnerability Name**: Broken Object-Level Authorization (IDOR)
* **Vulnerability ID**: LAB-001
* **OWASP Category**: A01:2021 — Broken Access Control
* **Location in Source Code**: `backend/app/api/orders.py` (`GET /api/orders/{order_id}`) & `backend/app/api/users.py` (`GET /api/users/profile/{user_id}`)

---

## Why It Is Vulnerable (Root Cause)
The backend endpoint accepts a direct object identifier (`order_id` in the URL path) and retrieves the corresponding database record without verifying that the authenticated user (`current_user.id`) owns the order or possesses administrative privileges (`current_user.role == "admin"`). 

The system erroneously assumes that knowing or guessing an entity's primary key constitutes authorization to view it.

---

## Security Impact
- **Confidentiality Breach**: Any authenticated user can enumerate and read the complete order details, item contents, and physical shipping addresses of every other customer in the database.
- **Privacy Violation**: Customer shipping addresses and purchase records are exposed to unauthorized third parties.

---

## How to Reproduce Locally
1. Start the lab in vulnerable mode (`SECURE_MODE=false`).
2. Log in as user `alice` (`alice` / `AlicePass123!`).
3. Notice in the Orders tab that Alice's order is Order `#1`.
4. In the browser console or using curl, issue a GET request for Order `#2` (which belongs to user `bob`):
   ```bash
   curl -H "Authorization: Bearer <alice_token>" http://localhost:8000/api/orders/2
   ```
5. Alternatively, on the frontend **Orders** view, enter `2` into the "Inspect order by ID" box and click **Fetch Order Details**.

---

## Expected Insecure Behavior
The server responds with `200 OK` returning Bob's order details, items, and shipping address (`456 Infiltration Blvd, Apt 9, Sector 7`) to Alice.

---

## Secure Remediation
1. Verify resource ownership before returning records:
   ```python
   if order.user_id != current_user.id and current_user.role != "admin":
       raise HTTPException(status_code=403, detail="Access denied")
   ```
2. Log authorization failures with structured metadata for security monitoring.

---

## Secure Code Example
```python
@router.get("/{order_id}")
def get_order_by_id(
    order_id: int,
    current_user: User = Depends(get_current_user),
    db: Session = Depends(get_db)
):
    order = db.query(Order).filter(Order.id == order_id).first()
    if not order:
        raise HTTPException(status_code=404, detail="Order not found.")

    # Secure object ownership verification
    if order.user_id != current_user.id and current_user.role != "admin":
        log_security_event(
            event_type="AUTHZ_FAILURE",
            details=f"User {current_user.username} denied access to order #{order_id}",
            username=current_user.username,
            db=db
        )
        raise HTTPException(
            status_code=status.HTTP_403_FORBIDDEN,
            detail="Access denied: You do not have permission to view this order."
        )

    return order
```
