# LAB-008: Server-Side Request Forgery (SSRF - Local Training Lab)

## Overview
* **Vulnerability Name**: Server-Side Request Forgery in Webhook / Catalog Import
* **Vulnerability ID**: LAB-008
* **OWASP Category**: A10:2021 — Server-Side Request Forgery (SSRF)
* **Location in Source Code**: `backend/app/api/admin.py` (`POST /api/admin/import-webhook`) & `backend/app/security/ssrf_validator.py`

---

## Lab Safety Rule
> **Educational Boundary**: This lab operates strictly locally within the Docker Compose network. Requests targeting external internet IP ranges are strictly prohibited and blocked by design. All SSRF training is performed against internal local mock services.

---

## Why It Is Vulnerable (Root Cause)
The webhook/catalog import feature accepts an arbitrary user-supplied URL and commands the backend HTTP client (`httpx.get(url)`) to make a network request without validating whether the target points to internal, sensitive microservices.

In vulnerable mode, an attacker can command the server to fetch confidential internal endpoints (such as `/api/mock-service/secret-vault`) that are never meant to be publicly accessible.

---

## Security Impact
- **Internal Service Pivoting**: Accessing internal APIs, cloud metadata endpoints (`169.254.169.254`), or private databases behind firewalls.
- **Credential & Secret Extraction**: Retrieving internal tokens, API keys, or infrastructure configuration.

---

## How to Reproduce Locally
1. Start the lab in vulnerable mode (`SECURE_MODE=false`).
2. Log in as `admin` (`admin` / `AdminPass123!`).
3. Navigate to the **Admin & Security** view.
4. In the **Safe Local SSRF Console**, select the preset:
   ```text
   http://backend:8000/api/mock-service/secret-vault
   ```
5. Click **Execute Fetch** or execute via curl:
   ```bash
   curl -H "Authorization: Bearer <admin_token>" -H "Content-Type: application/json" \
        -d '{"webhook_url": "http://backend:8000/api/mock-service/secret-vault"}' \
        http://localhost:8000/api/admin/import-webhook
   ```

---

## Expected Insecure Behavior
The backend connects to the internal mock vault and echoes confidential internal data (`TOP_SECRET_INTERNAL` / `LAB_INTERNAL_MICROSERVICE_KEY_9941_DEMO`) to the client.

---

## Secure Remediation
1. **Strict Path Allowlisting**: Restrict permitted target URLs to an explicit whitelist of safe public catalog paths (`/api/mock-service/public-catalog`).
2. **Private IP Blocking**: In production, resolve hostnames via DNS and reject private, loopback (`127.0.0.1`), link-local (`169.254.169.254`), and IPv6 private addresses.

---

## Secure Code Example
```python
ALLOWED_TARGET_HOSTS = {"backend", "localhost", "127.0.0.1"}
ALLOWED_SECURE_PATHS = {"/api/mock-service/public-catalog"}

def validate_ssrf_target(url: str, secure_mode: bool = False) -> str:
    parsed = urlparse(url)
    
    if parsed.scheme.lower() not in ("http", "https"):
        raise HTTPException(status_code=400, detail="Invalid scheme.")

    if secure_mode:
        # Enforce strict allowlist
        if parsed.path not in ALLOWED_SECURE_PATHS:
            raise HTTPException(
                status_code=403,
                detail="SSRF Protection: Access to internal endpoint path is denied."
            )
            
    return url
```
